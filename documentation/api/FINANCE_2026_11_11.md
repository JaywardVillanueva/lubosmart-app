# Finance additions — November 11, 2026

Laravel remains authoritative. Both endpoints require an unexpired Sanctum bearer token with `api:v1` and `role:<current role>`, and an operational account. Responses are private/no-store. Monetary overview values are integer PHP centavos; clients format them without recalculating allocations.

| Endpoint | Access | Response |
| --- | --- | --- |
| `GET /api/v1/finance` | Admin, Seller, Logistics, Rider | `data.role`, `data.amounts` (label → integer centavos), `data.discrepancies`, `data.legacy_rates` |
| `GET /api/v1/logistics/settlements?page=1` | Logistics | `data.entries` paginator, `data.totals`, `data.cash_model`, `data.can_record` |

Overview authorization is server-side: Seller sees own store, Logistics own operational centers, Rider own COD/compensation. Admin cannot read private Rider wage totals. Buyers continue using owned purchase/return endpoints. Unknown/foreign company filters cannot broaden scope.

Shipping entries contain parcel/provider identity, tracking, original allocation in centavos, expected product remittance, recorded receipt/reference/date if present, new shipping refund component if known and the existing COD reconciliation concept. Historical unknown refund splits are `null`, not invented zeros. `cash_model` is `logistics_retains_shipping`. Logistics tokens always receive `can_record: false`; no mobile cash mutation endpoint has been added.

Admin confirms actual full net-product cash receipt through the authenticated web `POST /logistics-settlements/{parcel}` action with `amount` (PHP, at most two decimals), unique `reference`, actual `received_on` (`YYYY-MM-DD`, no future date) and evidence `notes`. Shipping stays with Logistics. That action uses a transaction and audit record; no transfer is initiated. The platform receipt is a new Seller payout prerequisite.

Ordinary Seller `ParcelResource.recipient` now includes only name, city and province. Phone, street, barangay, region and ZIP remain available from the authorized own-parcel `GET /api/v1/seller/orders/{sellerOrder}/waybill` endpoint. Clients must not rely on ordinary list responses for contact/address labels. Flutter printing already fetches that endpoint.

Return read responses now include reviewed `responsibility` and `responsibility_reason`. No Buyer/Seller/Rider token can establish liability or record an Admin refund. Native Finance overview is reachable from Account for Seller/Rider; Admin/Logistics continue the existing website-only native navigation scope.

See [implementation and policy limitations](../FINANCIAL_FULFILLMENT_IMPLEMENTATION_2026_11_11.md). These additive endpoints are documented here; the older OpenAPI/Postman snapshots have not been regenerated.
